## 1. תקציר

היום יש בקורס 6 יחידות ו־16 שיעורים. החזרה הקיימת ("תרגול") בוחרת 3 שיעורים אקראיים ולא זוכרת במה הלומד טעה. בשחרור הזה:

1. **הקורס גדל ל־12 יחידות ו־64 שיעורים**, מאפס עד A2: 16 קיימים ועוד 48 חדשים (§4). המזהים הקיימים לא משתנים.
2. **חזרה מרווחת (Leitner)** על מילים ומשפטים שהלומד חלש בהם, עם כפתור "🧠 חזרה (N)". זה המנוע העיקרי לחזרה יומית (§7.2).
3. **טיפ פתיחה לכל יחידה** בעברית, לפני השיעור הראשון שלה (§7.3).
4. **הצעת הרשמה** לאורח אחרי השיעור הראשון (§7.4).
5. **אירועי אנליטיקה אנונימיים**, טבלאות ודשבורדים, כדי למדוד שימור ולמידה (§8).
6. **תיקון שני באגים שחוסמים הוספת תוכן:** כלל הפתיחה של שיעורים, ו־sanitize שמוחק שיעורים לא מוכרים (§6.7).

העבודה מתחלקת בין 5 סוכנים שעובדים במקביל, כל אחד ב־worktree משלו. לכל קובץ יש בעלים אחד בלבד (§10). השלד המשותף (טיפוסים, חתימות ופיצול קובצי התוכן) כבר נמצא בענף (§12).

## 4. הקורס המלא

**עקרונות:** 12 יחידות, 64 שיעורים. כל שיעור: **5 מילים** ו־**3–4 משפטים**. התרגילים נוצרים אוטומטית (`src/lib/exercises.ts`). הסדר הוא סדר היחידות ב־`course.ts`, ובתוך יחידה – סדר השיעורים בקובץ. שיעורים חדשים ביחידות 1–6 מתווספים **בסוף** היחידה (למשל `u1l4` בא אחרי `u1l3` ולפני `u2l1`).

המשפטים והמילים כאן מחייבים. כותב תוכן רשאי לשנות ניסוח **רק** אם:
- ה־validator נכשל (למשל מילה כפולה), **או**
- העברית או האנגלית לא טבעית.

כל שינוי כזה נרשם ב־handoff של הכותב (§10).

### 6.3 חזרה מרווחת (`shared/srs.ts` – קבועים; `src/lib/srs.ts` – מנוע; בעלים: backend)

```ts
type Box = 0|1|2|3|4|5;
SRS_INTERVAL_DAYS = [0, 1, 3, 7, 16, 35];
interface ItemState { box: Box; due: 'YYYY-MM-DD'; seen: number; wrong: number; last: number /*ms*/ }
type ItemStates = Record<itemKey, ItemState>;
REVIEW_LENGTH = 10; REVIEW_XP = 10; REVIEW_PIN_THRESHOLD = 3;
MAX_ITEMS_PER_USER = 3000; MAX_ITEMS_PER_REQUEST = 1000; MAX_DUE_AHEAD_DAYS = 400; SEED_SPREAD_DAYS = 6;
```

**אחסון:** `localStorage['baktana-english:srs:v1'] = SrsStore { v: 1, items, seeded, dirty: string[] }`.
- כל קריאה וכתיבה עטופה ב־try/catch.
- אחסון פגום או חסום → `emptySrs()`.

**`applyAnswers(store, answers, mode, now)`** – נקרא פעם אחת בסוף שיעור או חזרה שהסתיימו (יציאה באמצע לא נרשמת). `today = dateKey(now)`. לכל מפתח מאחדים את כל התשובות שלו:
- `correct` = כל התשובות למפתח נכונות. התשובות הן מהניסיון הראשון בכל תרגיל.
- `eligible` = קיימת למפתח תשובה שאינה `match`.

לפי המצב:

| מצב | תוצאה |
|---|---|
| פריט חדש, correct ו־eligible | `{box:1, due: today+1, seen:1, wrong:0, last: now}` |
| פריט חדש, אחרת | `{box:0, due: today, seen:1, wrong: correct?0:1, last: now}` |
| קיים, לא correct | `seen+1`, `wrong+1`, `last=now`. אם eligible: `box = min(box,1)`, `due = today` |
| קיים, correct, eligible, ו־`due ≤ today` | `box = min(box+1,5)`, `due = today + SRS_INTERVAL_DAYS[box]`, `seen+1`, `last=now` |
| קיים, correct, אבל עוד לא הגיע מועדו (או רק match) | `seen+1`, `last=now`. הקופסה והמועד לא משתנים (אין "דחיסה") |

- כל מפתח שעודכן נכנס ל־`dirty` (ייחודי).
- `mode` לא משנה את הכללים בשחרור הזה. הוא נשמר לשימוש עתידי.

**`dueKeys(store, now)`:** מפתחות עם `due ≤ today`. מיון:
1. `box` עולה.
2. `wrong/max(seen,1)` יורד.
3. `due` עולה.
4. מפתח (אלפביתי, לדטרמיניזם).

**`upcomingKeys(store, limit, now)`:** מפתחות שמועדם עוד לא הגיע, לפי `due` עולה ואז `box` עולה.

**`seedFromProgress(store, progress, now, rng)`** – פעם אחת (`seeded=false`):
- כל מילה וכל משפט של כל שיעור שהושלם (`completed[id] ≥ 1` ו־id קיים בקורס) מקבלים `{box:1, due: today + floor(rng()*7), seen:1, wrong:0, last: 0}`.
- `last: 0` מבטיח שכל מצב אמיתי מהשרת ינצח במיזוג.
- המפתחות האלה **לא** נכנסים ל־`dirty`.

**`useSrs(progress, signedIn)`:**
- טוען את המצב, ועושה seeding אם צריך.
- שומר כל שינוי.
- מחזיר `{ store, due, record(answers, mode) }`.
- (Should) כש־`signedIn`:
  - בהפעלה, באירוע `online` ואחרי `record`: אם `dirty` לא ריק, `api.putSrs(delta)`. התשובה (המצב המלא) ממוזגת עם `mergeItemStates`, ו־`dirty` מתרוקן מהמפתחות שנשלחו.
  - במעבר מ־false ל־true (התחברות): `api.getSrs()` → מיזוג → כל המפתחות המקומיים שאינם זהים לשרת נכנסים ל־`dirty` ונדחפים.
  - כישלון רשת: לא עושים כלום, וננסה שוב בפעם הבאה.

**מיזוג (`shared/srs-merge.ts`):** לפי D8.

**`sanitizeItemStates(input, now, limit)`** משמיט:
- מפתח לא תקין (`isItemKey`)
- `box` מחוץ ל־0–5
- תאריך לא אמיתי, או יותר מ־400 יום קדימה
- מספרים שליליים או לא שלמים
- `last > now` (יורד ל־`now`)
- מעבר ל־`limit` (ברירת מחדל `MAX_ITEMS_PER_USER`)

### 6.6 Supabase (`supabase/schema.sql`, תוספות אידמפוטנטיות; בעלים: backend)

```sql
-- (1) Keeps lesson ids that newer clients wrote when an older client saves progress without them.
create or replace function public.keep_completed_lessons()
returns trigger language plpgsql set search_path = '' as $$
begin
  if jsonb_typeof(old.data -> 'completed') = 'object' then
    new.data := jsonb_set(new.data, '{completed}',
      (old.data -> 'completed') || coalesce(new.data -> 'completed', '{}'::jsonb));
  end if;
  return new;
end; $$;
drop trigger if exists progress_keep_completed on public.progress;
create trigger progress_keep_completed before update on public.progress
  for each row execute function public.keep_completed_lessons();

-- (2) Spaced-repetition state (Should – F14).
create table if not exists public.srs_state (
  user_id uuid not null default auth.uid() references auth.users (id) on delete cascade,
  item_key text not null check (char_length(item_key) between 3 and 80),
  box smallint not null check (box between 0 and 5),
  due date not null,
  seen integer not null default 0 check (seen >= 0),
  wrong integer not null default 0 check (wrong >= 0),
  last bigint not null check (last >= 0),
  primary key (user_id, item_key)
);
alter table public.srs_state enable row level security;
drop policy if exists "own srs" on public.srs_state;
create policy "own srs" on public.srs_state
  for all using (user_id = auth.uid()) with check (user_id = auth.uid());

create or replace function public.merge_srs(items jsonb)
returns setof public.srs_state
language plpgsql security invoker set search_path = '' as $$
begin
  if jsonb_typeof(items) <> 'object' then raise exception 'invalid_srs'; end if;
  if (select count(*) from jsonb_object_keys(items)) > 1000 then raise exception 'too_many_items'; end if;
  insert into public.srs_state as s (user_id, item_key, box, due, seen, wrong, last)
  select auth.uid(), e.key, (e.value->>'box')::smallint, (e.value->>'due')::date,
         (e.value->>'seen')::int, (e.value->>'wrong')::int, (e.value->>'last')::bigint
  from jsonb_each(items) e
  on conflict (user_id, item_key) do update set
    box   = case when excluded.last > s.last or (excluded.last = s.last and excluded.box < s.box) then excluded.box else s.box end,
    due   = case when excluded.last > s.last or (excluded.last = s.last and excluded.box < s.box) then excluded.due else s.due end,
    last  = greatest(s.last, excluded.last),
    seen  = greatest(s.seen, excluded.seen),
    wrong = greatest(s.wrong, excluded.wrong);
  if (select count(*) from public.srs_state where user_id = auth.uid()) > 3000 then
    raise exception 'too_many_items';
  end if;
  return query select * from public.srs_state where user_id = auth.uid();
end; $$;
grant execute on function public.merge_srs(jsonb) to authenticated;

-- (3) Anonymous analytics events (Must – F11). Insert-only; dashboards read with the service role.
create table if not exists public.events (
  id bigint generated always as identity primary key,
  anon_id uuid not null,
  user_id uuid default auth.uid() references auth.users (id) on delete cascade,
  name text not null check (name in ('app_open','onboarding_complete','lesson_start','exercise_answer',
    'lesson_complete','lesson_abandon','hearts_out','review_start','review_complete','unit_intro_shown',
    'signup_prompt_shown','signup_prompt_accepted','signup_prompt_dismissed','signup_complete','identify')),
  lesson_id text check (char_length(lesson_id) <= 12),
  item_key text check (char_length(item_key) <= 80),
  ex_type text check (ex_type in ('choice-en','choice-he','match','build-en','build-he','listen')),
  correct boolean, first_try boolean,
  duration_ms integer check (duration_ms between 0 and 3600000),
  props jsonb not null default '{}' check (pg_column_size(props) < 1024),
  client_ts timestamptz not null,
  local_date date not null,
  local_hour smallint not null check (local_hour between 0 and 23),
  app_version text check (char_length(app_version) <= 20),
  platform text check (platform in ('web','pwa','android')),
  created_at timestamptz not null default now()
);
create index if not exists events_created_at on public.events (created_at);
create index if not exists events_anon on public.events (anon_id, created_at);
alter table public.events enable row level security;
drop policy if exists "insert events" on public.events;
create policy "insert events" on public.events
  for insert to anon, authenticated with check (user_id is null or user_id = auth.uid());
-- No select/update/delete policy: clients can never read events.

-- (Should) drop floods: more than 600 events per anon_id in one hour are silently skipped.
create or replace function public.events_rate_limit()
returns trigger language plpgsql security definer set search_path = '' as $$
begin
  if (select count(*) from public.events
      where anon_id = new.anon_id and created_at > now() - interval '1 hour') >= 600 then
    return null;
  end if;
  return new;
end; $$;
drop trigger if exists events_rate_limit on public.events;
create trigger events_rate_limit before insert on public.events
  for each row execute function public.events_rate_limit();

-- Raw events are kept 180 days (run daily with pg_cron where available; documented in docs/supabase.md).
create or replace function public.purge_old_events()
returns void language sql security definer set search_path = '' as $$
  delete from public.events where created_at < now() - interval '180 days';
$$;
```

### 6.7 תאימות לאחור ו־migration

#### 6.7.1 כלל הפתיחה (`src/lib/progress.ts`; backend)

```ts
/** Open when first in course, completed, the previous lesson is completed, or any later lesson is completed. */
export function isUnlocked(p: Progress, lessonId: string): boolean;
/** Not completed, but some later lesson is – a lesson added behind the learner's furthest point. */
export function isCatchUp(p: Progress, lessonId: string): boolean;
/** First uncompleted lesson after the furthest completed one; if none, the first uncompleted overall. */
export function currentLessonId(p: Progress): string | undefined;
```

- מזהים לא מוכרים ב־`completed` (מלקוח חדש יותר) לא נלקחים בחשבון.
- `__practice__` אף פעם לא נחשב שיעור.
- שרת ה־Express ו־`cloud.ts` כבר משתמשים ב־`isUnlocked`, ולכן התיקון חל עליהם אוטומטית.

#### 6.7.2 Sanitize סובלני (`shared/progress-merge.ts`; backend)

- מפתח ב־`completed` נשמר אם הוא קיים בקורס **או** תואם `^u\d{1,2}(l\d{1,2}|cp)$`.
- עד 500 מפתחות. השאר נזרקים.
- `__practice__` נזרק כמו היום.

#### 6.7.3 כללים נוספים

- **`Progress` ו־`baktana-english:progress:v1` לא משתנים בכלל.** כל מצב חדש נשמר במפתחות נפרדים:
  - `srs:v1`
  - `events:v1`
  - `anon-id:v1`
  - `signup-prompt:v1`
  - `intro-seen:v1`
  - `settings:v1` (מקבל שדה חדש אופציונלי)
- **Seeding** ללומדים קיימים: §6.3.
- **סדר פריסה (integrator):**
  1. SQL ב־Supabase.
  2. שרת עם migrations.
  3. האתר וה־APK בבת אחת.

  הטריגר `keep_completed_lessons` מגן על לומדים שעדיין משתמשים ב־APK ישן. לכן אין צורך לעכב את תוכן יחידות 7+.

## 7. התנהגות הפיצ'רים

### 7.1 פתיחה ותג "חדש!" (ui)

- במסלול, ליד שיעור שמקיים `isCatchUp`, מוצג שבב קטן "חדש!".

- "התחילו!" מוצג רק על `currentLessonId`.
- המסלול גולל אל השיעור הנוכחי בטעינה (`scrollIntoView({block:'center'})`).

### 7.2 חזרה מרווחת (backend: מנוע; ui: מסך, יצירה, חיבור)

- **App:**
  - `const srs = useSrs(progress, account.user !== null)`.
  - בסיום שיעור: `srs.record(result.answers, 'lesson')`.
  - בסיום חזרה: `srs.record(result.answers, 'review')` ו־`completePractice(p, REVIEW_XP)`.
- **LessonScreen:**
  - אוסף `ItemAnswer` לכל תרגיל, **בניסיון הראשון בלבד**.
  - בתרגיל match: תשובה לכל זוג. `correct=false` אם הייתה טעות שבה הזוג היה מעורב.
  - מחזיר אותן ב־`LessonResult.answers` (טיפוס פנימי של ui).
- **כפתור במסלול:**

  | מצב | הכפתור |
  |---|---|
  | `srs.due > 0` | "🧠 חזרה (N)" |
  | `srs.due = 0` ויש שיעור שהושלם | "💪 תרגול" |
  | אין שיעורים שהושלמו | מושבת |

- **כרטיס מוצמד:** כש־`srs.due ≥ REVIEW_PIN_THRESHOLD`, כרטיס בראש המסלול: "יש לך N מילים ומשפטים לחזרה" + "לחזרה".
- **`generateReview(srs.store, progress, rng, now)`** (`src/lib/review.ts`):
  - **בחירת מפתחות:** `dueKeys` עד 10. אם יש פחות מ־10, משלימים מ־`upcomingKeys`. אם עדיין פחות מ־4 פריטים, משלימים מ־`generatePractice`.
  - **מפתח מילה:** choice בכיוון אקראי, עם הסחות מאוצר המילים עד השיעור של המילה. אם יש 4 מפתחות מילים או יותר, מותר לאחד 4–5 מהם לתרגיל match אחד (לכל היותר אחד כזה).
  - **מפתח משפט:**
    - `build-en` (ברירת מחדל)
    - `listen` (בהסתברות 0.25)
    - `build-he` (בהסתברות 0.2, עם `heAlt` כמו בשיעור)
  - כל תרגיל נושא `itemKey`/`itemKeys`. מפתח שלא נמצא בקורס מדולג.
- **כללים:**
  - חזרה לא עולה לבבות (`hearts={null}`), ואפשר לעשות אותה גם עם 0 לבבות.
  - חזרה מזכה ב־10 XP, ונספרת ליעד היומי ולרצף.
  - חזרה לא פותחת שיעורים.

### 7.3 טיפ פתיחה ליחידה (ui)

- רכיב `UnitIntro` (bottom sheet או מסך) מציג:
  - כותרת היחידה
  - שבב רמה
  - `intro.goals` כרשימה
  - `intro.tip`
  - כפתור "יאללה, מתחילים"
- **הצגה אוטומטית:** כשמתחילים שיעור ביחידה שאין בה שיעור שהושלם, ושה־id שלה לא נמצא ב־`localStorage['baktana-english:intro-seen:v1']` (מערך מזהי יחידות). אחרי "יאללה" מוסיפים את היחידה למערך ופותחים את השיעור.
- **הצגה ידנית:** כפתור 📖 בבאנר היחידה, שפותח את אותו רכיב (בלי להתחיל שיעור).
- **הבאנר:** מציג שבב `level` (Pre-A1 / A1 / A1+ / A2).
- **`RichTip`:** רכיב יחיד שמרנדר `[[...]]` כ־`<bdi dir="ltr" lang="en">`. הפיסוק נשאר בתוך ה־bdi. משמש גם ל־`Lesson.tip`.

### 7.4 הצעת הרשמה (ui)

- **תנאי הצגה במסך סיום של *שיעור* (לא חזרה):**
  - `ACCOUNTS_ENABLED`
  - אין משתמש מחובר
  - מספר השיעורים השונים שהושלמו (`completed[id] ≥ 1`, מזהים בקורס) הוא **1**, ו־`dismissCount = 0`
  - **או** שהמספר הוא **5 ומעלה**, ו־`dismissCount = 1`
- **תוכן הכרטיס:** "שמרו את ההתקדמות שלכם 💾", טקסט משנה "חשבון חינמי שומר את ה־XP והרצף בכל מכשיר", וכפתורים "הרשמה" ו"אולי אחר כך".
- **"הרשמה":** `AuthScreen` עם `mode:'register'`. אחרי הרשמה מוצלחת חוזרים למסלול.
- **"אולי אחר כך":** `dismissCount += 1`, נשמר ב־`localStorage['baktana-english:signup-prompt:v1'] = { dismissCount, lastShownAt }`. אחרי 2 דחיות לא מציגים יותר.
- אחרי התחברות או הרשמה לא מציגים יותר.

### 7.5 מפתחות פריט ו־heAlt בתרגילים (ui, `src/lib/exercises.ts`)

- choice → `itemKey = wordKey(word)`.
- match → `itemKeys` מקבילים ל־`pairs`.
- build ו־listen → `itemKey = sentenceKey(lesson.id, index)`, `errors = sentence.errors`.
- בתרגיל build שבו עונים בעברית:
  - `answers = [he, ...heAlt]`.
  - המאגר כולל את מילות `he` ועוד מילות `heAlt[0]` שאינן ב־`he`. הן נספרות כחלק מההסחות. סה״כ ההסחות עד 4 + מילות ה־heAlt.
- `isCorrect` לא משתנה.
- **בדיקות:** כל תרגיל שנוצר בכל שיעור נושא מפתח תקין (`isItemKey`). תשובת `heAlt` נבנית מהמאגר ומתקבלת.

### 7.6 טיפ לשיעור (Should, ui)

אם יש `lesson.tip`, מוצג כרטיס `RichTip` לפני התרגיל הראשון, עם כפתור "הבנתי". כרטיס זה לא נחשב תרגיל.

### 7.7 Opt-out לאנליטיקה (ui + bi)

- `Settings.analytics: boolean`, ברירת מחדל `true`. `parseSettings` מטפל בשדה חסר.
- **בפרופיל:** מתג "שליחת נתוני שימוש אנונימיים".
- **App:** `useEffect(() => setAnalyticsEnabled(settings.analytics), [settings.analytics])`.
- **באונבורדינג:** שורה אחת: "אנחנו אוספים נתוני שימוש אנונימיים כדי לשפר את הקורס. אפשר לכבות בפרופיל."

### 8.3 מודול הלקוח (`src/lib/analytics.ts`; bi)

- **`track(input)`:**
  - אם האנליטיקה כבויה → לא עושים כלום.
  - אחרת: מוסיפים הקשר (`anonId`, `ts`, `localDate`, `localHour`, `APP_VERSION`, `platform`) ומכניסים לתור ב־`localStorage['baktana-english:events:v1']`.
  - התור מוגבל ל־500, והישנים נזרקים.
- **`platform`:**
  - `Capacitor.isNativePlatform()` → `android`
  - `matchMedia('(display-mode: standalone)')` → `pwa`
  - אחרת `web`
- **`flush()`:** בקבוצות של עד 50.
  - כש־`USE_SUPABASE`: `getSupabase().from('events').insert(rows)` (snake_case לפי §6.6, בלי `select`).
  - אחרת, כש־`ACCOUNTS_ENABLED`: `fetch('/api/events', { method:'POST' })`, עם `Authorization` מ־`loadAuth()` אם קיים.
  - אחרת: לא שולחים (התור נשאר מוגבל).
  - מוחקים מהתור רק אחרי הצלחה.
- **מתי מריצים `flush`:**
  - בהפעלה
  - כשיש 10 אירועים בתור
  - באירוע `online`
  - ב־`visibilitychange` ל־hidden
  - כל 60 שניות
- **`setAnalyticsEnabled(false)`:** מנקה את התור.
- **`identify()`:** `track({ name: 'identify' })` ואז `flush()`.

- Commit בענף ה־worktree של הסוכן (בלי push), עם הודעה ברורה.
